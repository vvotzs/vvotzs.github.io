Highlight

Free during Early Access: long-lived Node servers with WebSockets, in-memory state and long-running agent loops; one instance on the free plan

What you get

Netlify launched Netlify Server in Early Access on 2026-11-10: it runs your backend as a long-lived Node.js process that can hold WebSocket and Server-Sent Events connections, keep connection pools and caches in memory, and serve many concurrent requests from one instance. When nothing is using it the server scales to zero after five minutes and wakes on the next request. Netlify states that Netlify Server is free to use during Early Access. Credit-based Free and Personal plans allow one instance, while paid plans and Enterprise with credits allow three. It fits AI workloads well: an agent loop can run for a long time in one process, keep working state in memory and stream progress to the page over a WebSocket, and existing Express, Hono, Fastify or Koa apps deploy unchanged.

Conditions

The free period lasts only for Early Access; at general availability billing switches to reserved memory (GB-hours) plus active CPU time (vCPU-hours). One instance on Free and Personal, three elsewhere. Servers scale to zero when idle, so the first request waits for a cold start. Bandwidth, function calls and web requests bill as usual on the same project. APIs and behaviour may change during Early Access. Netlify CLI 27.17.0+ is required locally, or run netlify init inside a coding agent.

Steps

  1. Create or open a project on Netlify and confirm it is on a credit-based plan
  2. Upgrade to Netlify CLI 27.17.0 or later and run netlify init in the project to pull the latest agent skills
  3. Write the server entry as a long-lived Node process (an existing Express, Hono, Fastify or Koa app works as-is) and deploy it with the project
  4. Verify long connections and idle scale-down over WebSocket or SSE, and watch instance, memory and CPU usage on the project's Server page

Watch out

Free has a hard end: after GA you pay for resident memory and CPU, and an always-on backend can generate a bill quickly; the free plan has one instance and scales to zero after five idle minutes, so first requests wait on a cold start; state must live in Netlify Database or Blobs or it is lost when an instance is replaced; APIs and limits can change during Early Access.
